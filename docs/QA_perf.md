# FretLab 반응속도 측정 (6차 Q1)

2026-11-14, 워커 QA6. 기준 커밋 41ffdb0(main 80517df = 웨이브 1 + L6 머지). `vite preview`(빌드 결과, 127.0.0.1:4183) · Edge 157 헤드리스(Playwright 1.65) · Windows 11 · 16 코어 데스크톱. 임시 스크립트는 커밋하지 않았다(숫자만 옮김).

## 결론

**일반적으로 앱 자체의 반응은 한 프레임 안팎이다.** 탭에서 소리 시작 호출까지 **0.2 ms(PC) · 0.9 ms(폰 가정)**, 탭에서 눌림 표시까지 **2.4 ms · 14 ms**, 모드 전환·시트 열기는 **약 10 ms(두 프레임)** 이다. 실제로 귀에 들리기까지는 여기에 오디오 출력 지연 약 **50~58 ms**(측정 기기 값, 기기마다 다름)와 터치 패널 지연이 더해진다 — 이 둘은 앱이 줄일 수 없는 부분이고 이번 측정에 포함되지 않았다.

**느린 곳은 네 군데다.**

1. **첫 탭**: 중앙값 24 ms(PC) · 40 ms(폰), 10회 중 1회는 208~234 ms.
2. **폰에서 기울기 슬라이더 드래그**: 프레임 간격 중앙값 22 ms, p95 58 ms, 롱태스크 238건(최대 133 ms) — 눈에 보이게 끊긴다. PC 는 문제없다(중앙값 7.5 ms, 롱태스크 0).
3. **톤 샘플 로드**: 로컬에서는 45 ms(PC) · 124 ms(폰)지만 Fast 4G 가정에서는 0.66~0.74 초. 그동안은 합성음(KS)이 나고 로드가 끝나면 샘플 음색으로 바뀐다.
4. **첫 로드**: 폰 가정에서 화면이 뜨기까지 247 ms(로컬) · 631 ms(Fast 4G). PC 는 61 ms · 446 ms.

## 측정 방법과 한계

- 프로필 2개, 항목마다 10회. **PC** = 1440×900, 마우스, 스로틀 없음. **폰 가정** = 390×844 터치(`isMobile`·`hasTouch`) + CDP `Emulation.setCPUThrottlingRate` 4. 16 코어 데스크톱의 4배 감속이라 실제 중급 폰의 근사일 뿐이다.
- 시각은 전부 페이지 안 `performance.now()`. 입력 시각 = capture 단계 `pointerdown` 리스너(시트·모드 전환은 `click`). **합성 입력이므로 터치 패널·OS 입력 지연과 스피커까지의 출력 지연은 빠져 있다.** 참고로 측정 기기의 `AudioContext.baseLatency` 10 ms + `outputLatency` 40 ms(PC) / 48 ms(폰 가정)였다.
- ① `AudioBufferSourceNode.prototype.start` 를 감싸 호출 시각을 기록. ② `MutationObserver` 가 `.pressed` 를 본 뒤 `requestAnimationFrame` + 메시지 채널(그 프레임 커밋 직후). ③ `click` 뒤 더블 rAF. ④ 드래그 중 rAF 간격 + `PerformanceObserver('longtask')`. 드래그는 16 ms 간격 60스텝 왕복. ⑤ 첫 탭부터 마지막 `decodeAudioData` 완료까지 + Resource Timing. ⑥ Navigation Timing + FCP + 첫 `[data-pos]` 커밋 시각.
- **p95 는 n = 10 이라 사실상 최댓값이다.** 측정 화면의 rAF 주기는 약 6.9 ms(144 Hz)였다 — 60 Hz 화면에서는 "두 프레임"이 약 33 ms 다.
- 서비스워커는 차단하고 매번 새 컨텍스트(캐시 없음)로 쟀다. Fast 4G = CDP `Network.emulateNetworkConditions`(왕복 165 ms, 내려받기 약 8.1 Mbps) — 계획에 없던 추가 행이다.

## 개선 후보 (적용하지 않음 — 소유 밖)

- 기울기 드래그: 드래그 중에는 `.fretboard` 의 `--tilt` 만 바꾸고 설정 저장은 `change` 에서 한 번. `ScaleBar` 의 `positions()` 를 `useMemo` 로.
- 첫 탭: 줄일 방법이 마땅치 않다. AudioContext 는 사용자 제스처 뒤에만 켤 수 있다.
- 톤 로드: 느린 망에서 json 을 번들에 넣으면 왕복 1회(약 185 ms)가 준다.
